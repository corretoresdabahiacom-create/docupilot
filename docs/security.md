# Segurança (Fase 6)

| Tema                              | Implementação                                                                                                                                                                                                                                                                                                                             |
| --------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Senhas                            | PBKDF2-SHA256 (Web Crypto), salt de 16 bytes, iterações no próprio hash, máximo de 100.000 (limite do Workers); mínimo de 12 caracteres                                                                                                                                                                                                   |
| Sessão                            | Token aleatório de 256 bits; só o SHA-256 fica no banco; cookie `HttpOnly`, `SameSite=Lax`, `Secure` + prefixo `__Host-` em produção; rotação após 24 h; validade de 30 dias; logout apaga a sessão no servidor                                                                                                                           |
| CSRF                              | `SameSite=Lax` + checagem de `Origin` (ou `X-Requested-With`) nas rotas que alteram estado                                                                                                                                                                                                                                                |
| Enumeração de usuários            | Login devolve a mesma resposta para senha errada e e-mail inexistente (com hash descartável para igualar o tempo)                                                                                                                                                                                                                         |
| Força bruta                       | 5 falhas em 15 min bloqueiam o e-mail por 15 min (contador no Postgres, só escreve em falha)                                                                                                                                                                                                                                              |
| Anti-robô                         | Turnstile em cadastro, login e upload; em produção sem segredo a rota recusa                                                                                                                                                                                                                                                              |
| Upload                            | URL assinada de 5 min; checksum SHA-256 assinado; magic bytes e tamanho real conferidos; objeto inválido é excluído; tipos em lista fechada                                                                                                                                                                                               |
| Multi-tenant                      | Toda rota de workspace passa por `requireWorkspacePermission`; não-membro recebe 404; testes cobrem usuário B contra recursos de A                                                                                                                                                                                                        |
| Logs                              | `audit_logs` guarda só metadados; URLs assinadas e conteúdo de documentos nunca são registrados                                                                                                                                                                                                                                           |
| Texto extraído                    | Vem do navegador e **não é confiável**: o servidor higieniza controles, limita tamanho/lotes e recusa corrupção evidente; a interface o exibe como texto escapado, nunca como HTML                                                                                                                                                        |
| OCR                               | Consentimento revogável em `user_consents`, exigido pelo servidor (`CONSENT_REQUIRED`); código do OCR (worker/WASM) vem do jsDelivr por padrão, o que é dependência de terceiro: hospede cópia própria para eliminá-la                                                                                                                    |
| Campos extraídos                  | Vêm do navegador e **não são confiáveis**: o servidor reconfere cada item contra o texto armazenado (posição, trecho e padrão numa janela de ±80 caracteres) e regenera valor, confiança e rótulo; itens forjados são descartados e contados (testado). Resultado é gravado só com permissão de edição, após quota mensal                 |
| Exportação da comparação          | Gerada no navegador a partir de texto de terceiros: CSV neutraliza fórmulas (células iniciadas por `= + - @` recebem apóstrofo), Markdown escapa marcação, JSON é serializado, nome de arquivo é sanitizado; a tela renderiza trechos como texto, nunca como HTML                                                                         |
| Comparação                        | Sem rota nova: usa a leitura de páginas, que exige membro do workspace (não-membro 404) e `versionId` do próprio documento (outro documento 404); testado                                                                                                                                                                                 |
| Perfis de dados pessoais          | AES-GCM 256 em repouso, IV novo por gravação, AAD = perfil + usuário; chave só em segredo; sem chave: 503; listagem sem conteúdo; leitura/exportação/alteração/exclusão auditadas (só metadados); consentimento `pii_profile` exigido para criar/alterar; isolamento entre usuários (404) testado; D1 e busca sem dado em claro (testado) |
| Preenchimento de PDF              | Feito no navegador: o PDF e os dados não vão ao servidor; só `confirmado` é gravado; campo de outra pessoa é bloqueado; arquivo gerado fica sem proteção no aparelho do usuário                                                                                                                                                           |
| Documentos criados                | O servidor revalida todo conteúdo (`validateDoc`): lista fechada de nós/marcas, links só http/https/mailto, imagens só `data:` PNG/JPEG/GIF, limites de profundidade/nós/tamanho; o navegador valida de novo antes de salvar ou exportar; versão otimista (409)                                                                           |
| Exportação (PDF/DOCX/HTML/MD/TXT) | Gerada no navegador a partir do conteúdo saneado; HTML sem script, com CSP e texto escapado; Markdown escapado; nome de arquivo sanitizado; servidor só autoriza, conta cota e audita                                                                                                                                                     |
| Workflows                         | Passos em lista fechada, **sem passo externo** (nada sai do DocuPilot); entradas só de documentos do mesmo workspace; contexto com dados extraídos apagado ao terminar; log guarda contagens, nunca conteúdo                                                                                                                              |
| Aprovação                         | Em equipe, quem iniciou não aprova; em workspace pessoal, confirmação irreversível explícita (`confirm:true`); decisão em `approvals` + auditoria; `UPDATE` condicional impede decisão dupla                                                                                                                                              |
| Notificações                      | Só no app, por usuário (marcar como lida afeta só as próprias); sem Web Push                                                                                                                                                                                                                                                              |
| PDF                               | pdfjs sem XFA; arquivo tratado como dado                                                                                                                                                                                                                                                                                                  |
| Download                          | URL assinada de 15 min, só para membros com leitura; não é registrada em log                                                                                                                                                                                                                                                              |
| Busca                             | Sempre filtrada por workspace; índice de busca global, mas sem vazamento de conteúdo (testado)                                                                                                                                                                                                                                            |
| Cabeçalhos                        | `secureHeaders` do Hono                                                                                                                                                                                                                                                                                                                   |
| Segredos                          | Nenhum no repositório ou no front; segredos via `wrangler secret`                                                                                                                                                                                                                                                                         |

## Pendências conhecidas

- Custo de CPU do PBKDF2 contra o limite de 10 ms do plano Free **não foi medido** (só roda em Cloudflare real). Se estourar, reduzir iterações via `PBKDF2_ITERATIONS`.
- Rate Limiting binding do Workers (D3) ainda não está ligado; disponibilidade no plano Free não confirmada.
- A criptografia dos perfis **não foi testada em Cloudflare real** (WebCrypto no Workers) nem tem rotação de chave: trocar `PII_ENCRYPTION_KEY` invalida os perfis existentes.
- Valores decifrados ficam em memória do navegador durante o preenchimento; não há proteção contra extensões maliciosas ou máquina comprometida.
- Tiptap/`docx` não foram avaliados contra conteúdo adversarial além dos testes do validador; o servidor não confia no navegador (revalida), mas o editor roda na origem do app, então XSS por extensão do editor depende de manter a lista fechada de nós e marcas.
- Fase 6 não foi testada no Worker real (CPU de `validateDoc` em documentos grandes; CPU de 10 ms e TLS do postgres.js no Worker).

## Supabase: exposição pública do schema

O Supabase expõe o schema `public` por PostgREST (chaves `anon`/`authenticated`). A migração `0001` liga **RLS em todas as tabelas sem nenhuma policy** e revoga os privilégios de `anon`/`authenticated`: a API pública não lê nem escreve nada. O app acessa o banco só pelo Worker, com a connection string (segredo). Não verificado contra um projeto Supabase real (rodar o _Security Advisor_ do painel após aplicar as migrações).

## Empresas e convites (Fase 7)

| Tema              | Medida                                                                                                                                                |
| ----------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------- |
| Token de convite  | 256 bits aleatórios; só o SHA-256 fica no banco; exibido uma vez; uso único com consumo atômico; expira (1 h–30 dias); revogável                      |
| Enumeração        | token inválido, usado, expirado ou revogado → mesma resposta 404                                                                                      |
| Prévia pública    | só nome da empresa, do workspace, papel e validade                                                                                                    |
| Escalada de papel | só se concede/altera papel abaixo do próprio; `owner` nunca é concedido; sem auto-alteração                                                           |
| Isolamento        | toda rota de equipe passa por `requireWorkspacePermission` (não-membro = 404); convite e concessão de pasta só valem no workspace de origem (testado) |
| Pastas restritas  | 404 para quem não tem acesso; `view` não altera dados; concessões apagadas ao sair/ser removido                                                       |
| E-mail de membros | só aparece para owner/admin                                                                                                                           |
| Histórico         | só metadados; nunca conteúdo de documento                                                                                                             |
| Supabase          | `folder_members` com RLS ligado e sem policies (migração `0002`)                                                                                      |

Pendências desta fase: ver `docs/limitations.md` (Fase 7); nada foi testado no Supabase nem no Worker reais.
